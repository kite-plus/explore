# 公告与推广

> 状态：第一版已实现：公告和广告两类，置顶和信息流插位，网页、iOS 和后台 · 最近更新：2026-10-06

Explore 自己要说的话：站点公告、置顶内容，以及以后的推广。它们由维护者在后台发布，存在 Explore 的数据库里，和博客文章是两回事。官方博客（比如 Kite Official）以后作为普通博客收录，与本文无关。

## 0. 边界

[architecture.md §0.1](architecture.md#0-两个核心判断) 说 Explore 只保存博客清单和读者账号。公告与推广是第三类真相源数据：Explore 自己写的内容，不是博客文章的缓存，清空 `entries` 不影响它们。

- **广告必须看得出是广告。** 《广告法》要求广告具有可识别性，通过网络发布的要显著标明"广告"。标为广告的条目在每个出现的地方都带"广告"标记，后台没有关掉它的选项。不标明的软文不发。
- **不收集读者数据。** 不统计曝光和点击，不按读者定向，不放第三方广告代码。推广链接和文章链接一样直接打开，只加 `utm_source`，推广方在自己那边看到访问来自 Explore。以后如果要统计，只能是不关联任何人的总数，并且先修订本节。
- **不用第三方图片。** 读者看到的图片都经过 Explore 自己的服务器（[api.md §2.1.2](api.md#212-get-apiv1entriesidimage)），第一版的条目没有配图；要配图时走同样的转发。

## 1. 条目

| 字段 | 说明 |
|---|---|
| `kind` | `notice`（公告）或 `ad`（广告），决定标记 |
| `title` | 标题，1–120 字 |
| `summary` | 列表里的一两句介绍，最多 280 字，可空 |
| `body` | Explore 自己的正文，纯文本，空行分段，最多 2 万字；有 `url` 时可空 |
| `url` | 外部地址，只允许 http(s)；有它时条目直接打开这个地址，否则打开 Explore 上的条目页 |
| `source_name` | 列表里显示的名字，比如 Kite Plus 或推广方的名字，1–60 字 |
| `position` | 位置：`0` 置顶，排在第一篇文章之前；`N` 插在第 N 篇文章之后，1–50 |
| `audience` | 给谁看：空为所有人，`zh` 只给中文界面，`en` 只给英文界面 |
| `starts_at`、`ends_at` | 显示的起止时间，都可空；空的起点是立即，空的终点是一直显示 |
| `enabled` | 是否发布；草稿和撤下都是 `false` |

`body` 不支持 Markdown 和 HTML，链接写进 `url`。网页和 App 都没有 Markdown 渲染库，纯文本也免去了过滤 HTML 的问题；需要富文本时再加。

## 2. 显示

- **只在最新流的第一页**，并且没有按标签筛选时。按博客语言筛选不影响。推荐流和订阅流不插，往下翻的页面也不插。
- **同一种行。** 条目和文章用同一种行，头像、名字、标题、介绍的位置都一样；原来写时间的地方换成标记：公告是暖色的「公告」胶囊，广告是灰色描边的「广告」胶囊，置顶的再加一个图钉。没有链接检测和标签。
- **顺序。** 同一位置有多条时按开始时间新的在前。位置超过当页文章数的，排在最后。
- **打开。** 有 `url` 的直接打开，广告的地址加 `utm_source`；App 和文章一样用 Safari 视图打开，但不显示过渡页。没有 `url` 的是 Explore 自己的内容：网页打开条目页 `/notices/{id}`（英文 `/en/notices/{id}`），App 用 `GET /api/v1/notices/{id}` 原生显示同样的内容，不套网页。
- **条目页。** 标题、名字、标记、发布时间、正文，有 `url` 时底部一个"打开链接"按钮。`noindex`，不进站点地图。条目撤下或过期后返回 404。

现有的站点公告（`site_notice`，[admin-operations.md](admin-operations.md)）保留，适合"今晚维护"这类一行通知。

## 3. 接口

公开接口，按客户端地址限流，同 `GET /api/v1/entries`：

- `GET /api/v1/notices?audience=zh`：正在显示的条目，不含 `body`，按位置、开始时间新的在前。`audience` 取 `zh` 或 `en`，缺省只返回给所有人的条目。`Cache-Control: public, max-age=60`。
- `GET /api/v1/notices/{id}`：一个正在显示的条目，含 `body`；其他情况 `404`。

```json
{
  "id": "3",
  "kind": "notice",
  "title": "Kite for iOS 上架了",
  "summary": "在 App Store 搜索 Kite Explore。",
  "url": "https://apps.apple.com/app/id0000000000",
  "source_name": "Kite Plus",
  "position": 0,
  "published_at": "2026-10-06T00:00:00Z"
}
```

`published_at` 是开始显示的时间，没设开始时间时是创建时间。

管理接口见 [api.md §4](api.md#4-管理接口)：`GET`、`POST /api/v1/admin/notices`，`PATCH`、`DELETE /api/v1/admin/notices/{id}`。

## 4. 后台

"运营 → 公告与推广"：列表显示类型、标题、位置、给谁看、起止时间和状态，可以新建、编辑、发布、撤下和删除。表单按第 1 节的字段校验；类型选广告时提示"会显示'广告'标记"。
